# Plan: 2048 game (TypeScript, GitHub Pages)

## Context

Fresh repo, single purpose: a playable 2048 web game in TypeScript. The owner
will play it **on a phone** at
`https://anton-trautman.github.io/2048/` — mobile-first is a hard requirement.

## Global Constraints

- TypeScript, strict mode. Vanilla DOM only — **no framework**.
- Vite for build/dev, vitest for tests.
- Vite `base: '/2048/'` — the site is hosted under that GitHub Pages path.
  Every asset URL must work at that path.
- Mobile-first: fully playable at 360px viewport width, no horizontal scroll,
  touch swipe input (plus keyboard for desktop).
- Classic 2048 look: beige board, tile colors by value, 2048 tile in orange.
- Core engine is pure and deterministic: RNG injected (seedable), no DOM, no
  globals. UI and input are separate modules that consume the engine.
- No backend, no network calls, no external CDN assets.
- Board is 4x4. Win at a 2048 tile (player may continue), game over when no
  moves remain.

## File Layout (target state)

```
package.json, tsconfig.json, vite.config.ts
src/
  game/  types.ts, rng.ts, engine.ts, engine.test.ts
  ui/    render.ts, input.ts, game.ts
  main.ts, styles.css
index.html
README.md, DESIGN.md
```

## Task 0: Design

Produce `DESIGN.md` (repo root) covering: module boundaries and the core
engine API (exact TypeScript signatures for board creation, move, spawn,
game-over/win checks, state shape), board representation choice, input
handling approach (keyboard + touch swipe, with event details), UI state
management, styling approach (classic palette as CSS custom properties),
build/hosting config, testing strategy. ~150 lines max, no full
implementation. Commit as `docs: 2048 game design`.

## Task 1: Scaffold + core engine + unit tests

Scaffold the project (package.json with vite+typescript+vitest, strict
tsconfig, vite.config.ts with `base: '/2048/'`, index.html shell).
Implement the engine per DESIGN.md:

- `src/game/types.ts` — `Board` (4x4 grid of `number` tiles, 0 = empty),
  `Direction = 'up' | 'down' | 'left' | 'right'`, `GameState` (board, score,
  won, over, keepPlaying).
- `src/game/rng.ts` — seedable PRNG (`createRng(seed)` → `() => number`),
  plus `randomSeed()` from `crypto.getRandomValues`.
- `src/game/engine.ts` — pure functions: `newGame(rng)`,
  `move(state, dir, rng): { state, moved, gained }`, `canMove(state)`.
  Move semantics: slide + merge per row (each tile merges at most once per
  move), spawn one random 2 (90%) or 4 (10%) in an empty cell after any
  successful move, score += merged values, set `over` when no moves remain,
  set `won` once on first 2048 tile.
- `src/game/engine.test.ts` — vitest suite: slide without merge, merge with
  double-merge block (2 2 4 8 → left → 4 4 8 0... assert exact boards),
  all four directions, no-move returns unchanged state + moved=false,
  spawn fills exactly one cell, win on 2048, game-over detection.

`npm run build` and `npm test` must both pass. Commit.

## Task 2: UI layer

Implement per DESIGN.md:

- `src/ui/render.ts` — render a `GameState` to the DOM board (grid of tile
  divs, class per value), score box, "New Game" button, win overlay (with
  "Keep going") and game-over overlay. Re-render on state change (rebuild
  board; keep it simple — no virtualization needed at 16 cells).
- `src/ui/input.ts` — keyboard (arrows + WASD) and touch swipe (touchstart/
  touchend delta, 30px threshold, axis lock) both producing a `Direction`.
- `src/ui/game.ts` — glue: holds GameState + rng, on direction → engine.move
  → re-render; New Game resets.
- `src/main.ts` — bootstrap; `src/styles.css` — classic palette via CSS
  custom properties, responsive layout, board sized `min(90vw, 420px)`,
  tile colors for 2..2048 (and a fallback for super-tiles).
- `index.html` — board + score shell, no CDN references.

`npm run build` passes; the dev server serves a playable game. Commit.
